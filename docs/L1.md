# L1 待签与只读核验实现

当前：实现可配置的 PostgreSQL L1 流程，测试仅用受控 RPC fixture，**未进行真实测试网付款**。默认关闭；未知的 testUSD 合约地址不会被自动填入。testUSD 测试资产无美元价值；测试网地址、金额、memo 和交易关系公开。

## 接口及保证

L1 使用既有 `l1_invoices` / `l1_events`，并由迁移004补充 `l1_invoice_versions` / `l1_disclosures`，不会核销 L0 账单。`L1Service` 只允许配置中的 payer/recipient 及对应服务端角色访问；会计/admin 不能借此读取。当前已支持签名前不可变版本编辑和会计逐字段披露；不提供自动退款。会计只通过披露API读取，不能访问完整账单或附件接口。

顺序：创建 → 批准版本 → 只读前置检查及报价快照 → 指纹确认 → 生成待签请求 → 用户自行签署执行后提交哈希 → 只读核验 → 收款人确认。代码不调用广播交易方法。钱包待签请求包含唯一随机 UUID memo，避免历史同金额转账被分配给新单据；它是公开关联标识，不是账单内容或低熵摘要。

前置检查通过固定 testnet genesis 的 RPC 查询 ft_metadata、双方 storage_balance_of、付款人 ft_balance_of。未注册返回 STORAGE_REGISTRATION_REQUIRED；不会自行 storage_deposit。metadata 的 decimals、symbol 必须匹配配置；metadata 自称相同不能替代用户选择可信合约的证据，metadataSource 要保存已核实来源。

转账仅允许一个 `ft_transfer`，准确整数金额、接收方、随机 memo、固定 gas limit、1 yoctoNEAR deposit，不请求钱包授权。gas limit **不是 NEAR 网络费用报价或法币上限**，费用会变，用户需在钱包中审阅最终费用；应用服务费为零。当前不自动生成注册或退款交易。

确认绑定版本、审批、配置、报价期限和全部请求；quote 后 prepare 重查 storage/余额/metadata，并再次检查时间防 I/O 期间过期。进入待签状态即冻结，不允许重新报价。超时只记 UNKNOWN，刷新/重建服务恢复同一记录，不生成新支付尝试。

PostgreSQL 行锁和 revision CAS 防止迟到响应覆盖新状态；同幂等键同参数返回原记录，异参数拒绝。HMAC 事件索引唯一。业务字段、原始 receipt、审计时间线都在 AES-GCM 载荷内，AAD 绑定单据 ID；索引仅泄漏数量、ID、revision、同键/事件相等关系。RPC 依然是可信服务方声明，并非轻客户端证明。

核验必须是 FINAL 的准确 direct ft_transfer、可达 receipt 图、唯一直接合约 transfer event、正确账户和整数金额，还要与生成请求的 gas 和完整 args（含随机 memo）相同。任意 tx hash、历史同金额交易、nested logs、非最终结果、模拟引用都不能核销。未最终为 UNKNOWN；矛盾为 REVIEW_REQUIRED。只读 RPC 出错不会当付款失败并重付。

## 报价期限与链上执行时间

`ft_transfer` 协议本身没有应用报价截止时间，导出的请求不能被服务端撤回。应用通过最终收款 receipt 的 `block_hash` 查询同一固定网络 RPC 的 `block`，校验返回 header.hash 并只使用精确十进制字符串 `timestamp_nanosec`；不使用会丢失精度的旧 numeric timestamp。只有执行时间在服务端 confirmedAt 与 quote.expiresAt 之间才结清。过期执行、缺失可信时间或时钟不一致进入 REVIEW_REQUIRED，可能已经到账，绝不可自动重付。

新增官方依据：https://docs.near.org/api/rpc/block-chunk 的 block_id 查询；https://raw.githubusercontent.com/near/nearcore/master/core/primitives/src/views.rs 的 BlockHeaderView（timestamp_nanosec 使用 dec_format，legacy timestamp 明确不建议使用）。这里仍依赖可信 RPC 和服务端时钟，不是独立链证明。

测试补充到 11 个子场景：过期执行不结清、同时核验 revision CAS、事件插入失败回滚。没有真实 RPC 或真实交易。

## 版本编辑、附件和逐字段披露（本轮完成）

- `PATCH /api/l1/invoices/{id}` 接受 `{expectedVersion,payload}`。payload仅允许amountAtomic、purpose、可选attachment；收款账户、网络、合约及精度保持允许配置，额外字段拒绝。编辑创建新的加密版本行，SQL触发器拒绝UPDATE/DELETE；旧批准与报价保存在密文历史并失效，必须重新审批确认。
- `AWAITING_SIGNATURE`、`SUBMITTED`、`UNKNOWN`、`REVIEW_REQUIRED`和已核验状态禁止编辑，不会借新版本开放重付。expectedVersion加行锁让并发编辑或edit/prepare只有一方成功。原创建幂等键绑定原v1输入，即使后来编辑仍返回同一账单；同键异参数409。
- 原有无版本表的v1密文记录在服务端持有正确密钥时补录，后续版本缺失则拒绝，不凭当前字段重建历史。版本内容包含允许网络/资产/收款条件及完整性绑定，金额/用途/附件不出现在索引列。
- attachment只接受 `{name,type:"text/plain",content}`，按UTF-8限制64 KiB。下载以attachment和text/plain响应、nosniff、no-store，不执行HTML或主动内容。
- 会计公开账户来自真实认证配置中唯一 `accountant` 角色，服务端注入授权策略；不是前端角色声明，也不是新的身份切换入口。不修改支付配置指纹，因此增加会计策略不会使旧账单无法读取。会计映射改变后旧接收人访问失效。

| API | 权限和返回 |
| --- | --- |
| GET /api/l1/invoices/{id}/attachment?version=N | payer/关联recipient读取指定不可变版本附件 |
| POST /api/l1/disclosures | payer指定invoiceId、version、recipient、fields、expiresAt；最长期限30天，默认不选字段 |
| GET /api/l1/disclosures | payer见授权管理元数据；会计仅见本人仍有效授权 |
| GET /api/l1/disclosures/{id} | 仅指定会计，在每次请求重新核对版本、字段、到期与撤权 |
| GET /api/l1/disclosures/{id}/export | 同一鉴权与字段投影，不增加隐藏字段 |
| GET /api/l1/disclosures/{id}/attachment | 同一授权且必须显式包含attachment字段 |
| DELETE /api/l1/disclosures/{id} | payer撤权，密文审计记录事件、版本与授权ID，重复撤权安全 |

允许字段：amountAtomic、purpose、asset、network、payer、recipient、attachment、settlement。attachment字段读取仅给元数据，内容通过重新鉴权的下载路径返回。settlement只给该版本状态/核验与收款确认摘要，不含原始receipt、交易哈希、账户或其他版本证据；它不是会计独立链验证证明。所有其他字段不会随导出附带。即使携带If-None-Match或If-Modified-Since，撤权后的新请求仍403而非304。撤权不能删除用户已经保存的文件。

旧版本授权不会自动升级至新版本；新版本的结算不会显示在旧版本授权里。L1 receipt仍绑定准确网络、允许合约、版本报价、随机memo、唯一事件和执行时间；没有接受客户端上传模拟证据的入口。

## 只读通道与退款边界

SDK仍固定 `@hot-labs/near-connect@0.11.4`，只使用NEP-413登录；没有交易签名/广播调用。RPC仅调用status、query（view_access_key、受限call_function: ft_metadata/storage_balance_of/ft_balance_of）、tx_status、block。每次业务RPC前检查status的chain_id为testnet、genesis_hash与配置一致且非syncing；HTTPS禁止重定向。query采用final，tx_status要求FINAL，执行区块hash必须匹配receipt，timestamp_nanosec用BigInt检查批准确认窗口。信任配置RPC而非独立轻客户端证明。本轮只使用mock RPC，未查询真实账户。

NEAR直接ft_transfer没有可任意撤回的自动退款。本项目不生成退款交易，异常保持人工核对，不把UNKNOWN当失败重付。未来Confidential Intents退款属于不同适配器且L2仍BLOCKED，不能以此替代直接转账退款。
