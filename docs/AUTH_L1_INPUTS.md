# 真实认证、钱包与 L1 的最小输入

2026-10-25 更新。当前真实登录默认关闭，L1/L2 支付硬禁用。不需要私钥、助记词或新的链上授权。

## 已实现与验证边界

已核实官方 NEP-413，并独立实现 Borsh 编码、协议标签、SHA-256 后 Ed25519 验签。服务端挑战持久化、nonce 原子消费、随机会话签发/轮换/退出、配置式账户成员映射、固定网络只读 FullAccess 查询均已实现。

已有 PostgreSQL 并发/回滚/重放/退出竞态实测；NEAR 查询只用 mock，签名只用公开协议示例和内存测试 fixture。没有连接钱包或真实账户，不声称真实钱包登录已验收。旧自定义 login-proof 格式不用于新登录。详见 NEAR_AUTH.md。

只读 receipt 拉取和直接 ft_transfer 核验模块已实现，但也仅通过 fixture/mock 测试；没有测试网付款，不将 READ_ONLY_MATCH 用来结清账单。

## 下一步最少需要确认的公开信息

1. **登录 origin**：预期精确 HTTPS 域名/端口；本地开发是否允许 loopback HTTP。
2. **已有测试网公开账户与角色**：哪些现有账户对应付款人、收款人、会计或管理员。不需要开户，不提供钱包私钥或助记词。
3. **钱包选择**：希望使用的现有钱包，以及它支持的 signMessage/NEP-413 返回方式；据此实现并验证客户端连接。当前没有 web-wallet callback 桥接。
4. **可信只读 RPC 与网络锚点**：选择公开 HTTPS NEAR testnet RPC，并核实其 testnet genesisHash。实现者随后只读核实实际结构和最终性；配置缺失不会自动选择未知服务或切换主网。

以上公开信息用于准备可审阅配置，不自动授权开启真实账户连接、部署或执行交易。

## L1 付款另外需要的条件

- 允许的 testUSD 合约及官方出处、可信 metadata/decimals；testUSD 不是 USDC，无美元价值。
- 付款/收款测试网公开地址、退款目的地、单笔金额和费用上限、到账条件、报价期限。
- 收款方独立核对路径、真实 receipt 与代币合约可信证据。
- 最终由用户另行明确批准限定账户/资产/金额的测试交易，并亲自在钱包签署；当前没有该授权。

日后服务若需要 API 凭证，只能在受控环境注入，不能放进聊天、公开仓库或源码包。外部账户创建、持久权限、公开推送和部署也需分别确认。

## 可继续安全实现的工作

可以继续完善钱包客户端协议适配、只读测试网资产/网络核实、认证限流和过期记录清理、纯验证反例与运维测试。这些代码和只读工作不需要钱包私钥，也不代表允许执行链上交易。实际账户连接与测试操作应在条件明确可审阅后由用户确认。

L2 仍需已验证的 Confidential Intents 能力、历史查询权限、实际到账及退款证据；继续 BLOCKED。认证和 PostgreSQL 测试通过不改变 L1/L2 交付等级。
