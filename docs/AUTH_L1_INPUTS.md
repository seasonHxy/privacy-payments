# 真实认证、钱包与 L1 的最小输入

这些是后续实施条件，不要求用户现在提供密钥，也不构成开户、转账或部署授权。当前 L1/L2 保持硬禁用。

## 已安全实现

`src/login-proof.ts` 是独立离线 Ed25519 签名验证函数，绑定协议标识、准确 origin、用途 login、账户标识、nonce、签发时间与不超过 5 分钟的期限。仅接受 HTTPS，或 HTTP + loopback。拒绝已消费标记、过期/未来时间、篡改账户/nonce/域名/用途、畸形公钥或签名。测试密钥只在测试内存中生成和使用，未保存、注册到链或作为钱包使用。

它返回 OFFLINE_PROOF_ONLY，不签发会话；没有接入 `/api/demo/session`。它不是 NEP-413 编码实现，也不是已经完成的钱包登录。调用方必须从可信服务端存储加载 expected challenge，从已验证的账户密钥来源获得 authorizedPublicKey，并原子消费 nonce 后才能签发会话。持久 nonce 存储、链上账户密钥解析/撤销检查和真实会话签发均未实现。登录证明不能作为付款授权。

## 后续最少需要用户确认的公开信息

| 项目 | 用户提供/确认 | 实现者随后必须验证 |
| --- | --- | --- |
| 登录域名 | 预期最终 HTTPS origin（精确域名/端口），以及本地开发是否启用 | 同源策略、挑战域名、回调白名单；不得使用任意来源回调 |
| 人员身份 | 付款人、收款人、会计的身份认证方式及角色；是否采用现有身份提供方 | 身份与 workspace membership 的真实绑定；不能继续用自选演示角色 |
| 测试网络 | 明确选择 NEAR testnet | RPC 网络身份、最终性语义；不自动改用主网 |
| 测试资产 | 可核实的 testUSD 合约标识/官方出处 | 合约代码及可信 metadata 中 decimals/资产归属；testUSD 不等于 USDC、无美元价值 |
| 已有账户 | 用户已有的付款/收款测试网公开账户名或地址、退款目的地 | 账户存在、收款关联与授权公钥；无需助记词或私钥 |
| 钱包 | 用户希望使用的现有钱包和支持的登录签名/交易请求形式 | 对应官方协议编码和验签；签名方法/目的地/权限白名单，不请求持久全权限 |
| 付款条件 | 单笔测试金额上限、目标到账条件、费用上限、报价期限、退款要求 | 整数精度、实际网络费用与精确输出是否可达，不能用固定模拟费用 |
| 只读 RPC | 可用的官方/可信测试网 RPC 选择 | 可信网络固定、receipt/event、发送方、合约、接收方、金额与 finality 联合核验 |
| 最终执行授权 | 另行明确同意一次限定账户/资产/金额的测试交易，由用户本人签署 | 在实际条件可审阅后再执行；本轮没有该授权，也没有交易 |

如果日后服务需要 API 凭证，应在受控环境注入，不在聊天或公开仓库提供。永远不索取助记词、钱包私钥或主网资金。外部账户创建、持久授权、公开部署也需另行明确范围。

## 工程阻塞与下一步

先实现服务端一次性 nonce 的持久原子消费、真实登录与成员映射；再实现官方钱包协议适配和 NEAR 测试网允许资产的只读核实。完成可信 RPC receipt 拉取、付款请求白名单和收款独立核对后，才可在另行授权的条件下测试 L1。

L2 另外需要已验证的 Confidential Intents 通道、历史查询权限、实际到账/退款证据和隐私边界；目前仍 BLOCKED。PostgreSQL 和离线签名验证通过不改变 L1/L2 等级。
